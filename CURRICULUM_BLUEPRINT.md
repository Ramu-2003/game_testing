# Curriculum Blueprint

## Target and release rule

The target is 1,000 levels for each configured course: ten phases with a capacity of 100 levels per phase. The current catalog is smaller. Empty capacity is not counted as content, and generated or unreviewed exercises must not be labeled as published lessons. Release a lesson only after its instructions, starter, expected behavior, checks, hint, and explanation have been reviewed together.

The existing phases already establish a useful topic sequence. This blueprint expands those topics while preserving the project's five configured courses.

## Batch authoring and review gates

1. Assign each lesson a stable course/phase/level identifier, topic tags, difficulty, estimated time, prerequisites, and activity type.
2. Write an objective, complete task, constraints, starter, example or expected behavior, progressive hint, and explanation before implementation.
3. Select an evaluation mode supported by that activity. Source-rubric review must be labeled as review guidance; it must never claim that submitted code ran.
4. Check prerequisite references, level continuity, duplicate titles/tasks, starter syntax where a runtime exists, and expected behavior against independent examples.
5. Mark the lesson draft until a reviewer has checked correctness, accessibility, clarity, and evaluation. Only then make it available as published content.
6. Keep the per-course target count separate from reviewed/published counts. A full phase slot is not a lesson.

The current export pipeline keeps browser and server catalogs synchronized and serves one phase at a time. It does not yet implement versioned draft/review/published records or automated execution of source-rubric exercises. Those remain release work; this blueprint is a coverage plan, not a claim that the missing lessons exist.
